# 报告版本与历史

研究项目内点击“研究报告”，默认读取最近保存的一份报告；没有报告时显示生成入口。打开、刷新、翻页和切换版本均不创建快照。点击“生成报告快照”或“生成最新快照”才保存新的版本。

“历史报告”在同一窗口按保存顺序展示版本，每次20份，可以加载更早报告或刷新列表。研究继续更新不会覆盖旧报告；切换到历史版本后，预览、固定链接与Markdown下载都指向该版本。旧报告记录的“截至第几条研究记录”是生成时的事件位置，不是研究覆盖率。

列表读取失败保留已有列表和正在查看的报告。正文读取失败保留原预览并提示错误，可重试读取。关闭窗口或切换项目后，晚到的请求不会重新打开报告，也不会带入其他项目。生成请求的返回如果未能确认，先刷新历史查看保存结果，避免盲目重复生成。

## 接口

- GET /api/research/sessions/{session_id}/reports：元数据列表，limit默认20、范围1至100；before为上页返回的next_cursor（报告ID）。
- 返回items、next_cursor和has_more。items仅包含id、session_id、event_seq、created_at和sha256，不包含报告正文、源码、身份材料或运行配置。
- 按SQLite插入顺序倒序读取，游标绑定项目；未知项目、未知或跨项目游标返回404，非法页大小返回422。使用一致读事务，不提交调用方事务。
- 新插入的报告不挤占已有游标的更早页面；刷新第一页可以看到新报告。
- POST同一路径仍生成不可变报告，原报告详情、下载和固定链接契约保留，无数据库迁移。

reports.js负责列表与正文独立请求序号，共享弹窗生命周期标识。它以属性描述符组合Alpine组件，保留现有getter行为；没有增加独立报告中心。

验收：prototypes/qa/research_report_history_browser.py覆盖无自动写入、分页与并发新增、原快照下载、失败保留、乱序响应、关闭/跨项目隔离、固定链接与窄屏。测试仅写入Kali的隔离验收库；报告历史功能不代表研究执行器已接入。
