# 测试身份材料

入口：研究工作台 → 研究材料 → 管理身份。

本功能保存测试账号与登录态配置，不尝试登录，也不向目标发送请求。导入后的“已导入”只表示材料已保管，不代表账号可用或登录成功。

## 使用方式

1. 项目中先提供网站/运行环境地址。纯代码研究不需要测试身份。
2. 在 Kali 的 /home/kali/.local/share/cairn/identity-imports/ 中准备 JSON 文件。打开身份面板会建立导入目录；目录权限须为700，文件权限须为600，所有者须为运行 Cairn 的 kali 用户。
3. 页面填写容易区分的名称，例如“普通成员 A”，以及文件名，例如 member-a.json。网页不接收文件内容、密码或令牌。
4. 导入后只显示名称、类型、绑定地址、版本和状态。需要更新登录态时点击“更换材料”；不再需要时点击“撤销”。

源文件不会被移动或删除，由用户继续保管。导入只接受该私有目录中的普通 JSON 文件名，不接受路径、符号链接或硬链接，文件上限64 KiB。错误不会回显文件内容。

以下均为占位示例，按实际测试账号填写，不要把真实秘密放入 Git 或普通 Hint。

### 普通账号材料

用于保存用户名和密码，不预设表单登录流程：

~~~json
{"type":"account","username":"测试用户名","password":"测试密码"}
~~~

### HTTP Basic

只有目标明确使用 HTTP Basic 时使用：

~~~json
{"type":"basic","username":"测试用户名","password":"测试密码"}
~~~

### 请求头

~~~json
{"type":"headers","headers":{"Authorization":"Bearer 测试令牌"}}
~~~

### Cookie

~~~json
{"type":"cookies","cookies":{"session":"测试会话值"}}
~~~

## 环境与版本

身份绑定网站的协议、主机和端口。项目更换该范围后，旧身份显示“环境已变更”，不会自动关联新地址。显式更换材料后才更新绑定，并增加版本。

运行中或正在暂停时不能修改身份。没有运行环境时不能导入或更换，但可以撤销已有身份。撤销会清空数据库记录中的密文和 nonce，保留元数据和事件；后续可从用户保管的本地文件重新导入。

## 保存与恢复

服务端使用 AES-GCM 加密，数据库只保存密文；相关事件、项目详情与报告不包含导入的秘密内容。加密关联项目、身份、版本与目标地址。

随机密钥存放在 /home/kali/.local/share/cairn/identity-vault/master.key，独立于数据库，目录权限700、文件权限600。恢复已保管身份时，需要配套恢复原数据库和原密钥。数据库备份不包含此密钥，不要把密钥同步进仓库。密钥缺失或被替换时，系统会拒绝新导入，不会悄悄生成替代密钥。

当前只交付配置保管，没有明文读取 API，也未接入执行器。测试均使用 /tmp 中的虚构材料。
