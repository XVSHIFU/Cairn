# 源码材料与版本

入口：研究工作台 → 研究材料 → 浏览源码。

## 日常使用

新建项目时填写已准备好的 Kali 本地代码目录，首次授权后自动保存一份源码快照，不再弹出第二次授权。已有项目可点击“保存新快照”。目录读取失败会显示原因，项目本身仍保留，可修正材料后重试。

源码面板可以搜索相对路径、查看文件原文、切换已保存版本。长文件每段显示300行；填写起止行并点击“定位”可跳到对应段落。“保留所选代码”最多保存400行，保留原始换行、文件路径、行号、快照引用、完整文件和片段的SHA256。材料进入现有证据工作台和报告，不自动生成发现或漏洞结论。

文件内容在服务端保存后固定。修改或删除原文件不会改变旧快照或旧证据。更换项目代码目录后，旧快照会标记为旧目录材料，仍可查阅和引用。查看已保存文件只读数据库，不重新扫描目录。创建新快照和人工选行需要项目不处于运行中或正在暂停的状态。

## 采集范围与限制

- 接受 UTF-8 文本，无固定语言准入名单。未知扩展名仍可以读取，标为text；当前语言标签按文件名/扩展名判断，不代表完成框架识别或代码审计。
- 默认跳过隐藏条目，以及node_modules、.venv、venv、vendor、build、dist、__pycache__等依赖与构建目录。
- 跳过符号链接、硬链接、特殊文件、跨挂载边界、非UTF-8文本、读取时变化或无权限的条目；代码目录的祖先路径也不能包含符号链接。
- 每次最多2000个文件、16 MiB内容；单文件512 KiB；遍历最多10000个目录条目、32层深度。
- 15秒采集检查预算在遍历和读取间检查，不是强制中断操作系统I/O的硬超时。
- 最多展示200条跳过详情。任何跳过项都显示为部分采集，并明确列出限制。
- 内容摘要只标识本次采集的文件和内容；整个目录采集不是原子操作，也不是Git commit。不会执行Git命令。
- 当前不会执行源文件、安装依赖、启动应用、调用模型或形成审计结论。源码材料模块完成不代表白盒自主审计已接入。

快照内容存储在现有SQLite库中，随数据库备份保存。没有额外复制源码到Windows仓库；代码同步只包含功能实现、文档与夹具测试脚本。

## 对照两个版本

在“浏览源码”面板中点击“对照版本”，选择基准版本和对照版本。至少保存两份快照后才可从该入口打开；也可以在面板中选择同一版本检查无差异状态。

文件列表分为内容变化、仅基准版本有、仅对照版本有；相同内容计入统计。这里的出现/缺失只描述快照中的记录，不证明磁盘文件真正新增或删除。部分采集与跨目录对照都会注明限制，不自动推断重命名或修复成功。

逐行对照显示两侧行号、上下文、增加/移除的文本和行尾标记，包括LF、CRLF、CR及没有末行终止符。内容按纯文本渲染。可交换方向，也可以打开任一侧原快照文件继续浏览和选行。

逐行对照每侧最多64 KiB、1200行，单行最多8192字符；超过时不计算差异并说明原因，仍可查看已保存原文件。差异输出最多1600行，截断会明确提示，省略不能理解为没有变化。

代码证据中新增“查看原快照与代码上下文”，返回证据绑定的文件版本及原行号。读取失败时不保留另一版本的代码冒充上下文。快速切换对照版本时，旧请求的迟到响应不会替换当前结果。

对照接口只读取现有快照，不创建事件、不修改发现、不读取当前源码目录。源码对照并不执行修复复测，也不判断漏洞状态。
